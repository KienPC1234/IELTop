# AGENTS.md - Mandatory rules for IELTop

Offline IELTS study app, open source. Stack: .NET 10 + .NET MAUI / WinUI 3 (Windows only) + React/Vite + ONNX Runtime + SQLite (sqlite-net-pcl). Shared logic and models live in `IELTop.Core`.
Every agent and every commit must follow this file.

## Architecture (read this first)

- Main window: `BlazorWebView` (HostPage `wwwroot/index.html`), bridge via `JsBridge` + `[JSInvokable]`. Exam window: plain WebView2 + HTTP bridge (`StaticFileServer` on loopback, `/api/*` + SSE, no Blazor runtime). Both share one `BridgeRouter`.
- `bridge.ts` `call()` tries Blazor first, then HTTP. `window.chrome.webview` postMessage is valid only on the exam window (`http:` loopback); on the main window (`https://0.0.0.1` Blazor virtual host) it is Blazor-internal and must be ignored.
- Shared logic belongs in `IELTop.Core`. Web UI never scores, reads DB, calls ONNX, or constructs `HttpClient` directly.

## 1. UI/UX

- English-only UI. No em dash (U+2014), en dash (U+2013), or decorative emoji. Icons: `lucide-react` components only; no text glyphs (`x`, arrows) as labels, no hand-drawn paths.
- Every rendered control works or is `disabled` with a clear reason. No dead buttons, no "Coming soon", no demos. Main flows run end to end: click, feedback, result or plain error. A button that will certainly fail must be disabled upfront, not fail on click.
- No raw tech terms in UI (`InferenceSession`, `Tensor`, `DbContext`, `NullReference`, `StackTrace`). Log fully; show one short sentence: cause plus fix. Good: "The model could not be opened. Check the file in Content/Assets/Models."
- One screen, one job. Sidebar has at most 7 items, each opening a real screen. Exam Editor is a tab inside Paper Library, not a sidebar item. Guide is a shared static `GuideDialog.tsx` behind a "?" header button, not a sidebar item; no bridge route needed.
- Operations over 1s show a waiting state (disabled button, "Working..."). Every input has a placeholder; multiline input uses top-aligned `<textarea>`. Minimum 12px font, readable contrast. Basic keyboard support: correct Tab order, Enter confirms.
- Single style system: Tailwind utilities plus shadcn tokens in `src/styles.css` (`--background`, `--foreground`, `--card`, `--primary`, `--border`, `--ring`), light and dark palettes. Changing a token changes it globally. No Mantine/Chakra/MUI, no chart library (SVG/CSS only), no ad-hoc undefined classes. shadcn components go in `UserInterface/src/components/ui/` (add via `npx shadcn@latest add <name>`); app composites go in `UserInterface/src/components/`. Any style-system change must update this section first with a reason.
- Exam frame uses its own tokens (`--exam-header`, `--exam-bar`, `--exam-surface`, `--exam-block`, `--exam-instruction`, `@theme` `bg-exam-*`); never reuse `--card`/`--muted` there. IDP computer-delivered look: dark header, gray body, bordered guide block, white question block, bottom part/question strip. Square corners only (`rounded-none`/`rounded-xs`, never `rounded-lg/xl`). Use full width; no large empty side margins.
- Theme Light/Dark/System, default `System`, stored in `AppSettings.UiTheme`, applied as `.dark` on `<html>` via `src/lib/theme.js`. Never read `prefers-color-scheme` inside components. Study helpers (hero cards, empty-chat chips, Speaking 3-step stepper) reuse existing routes; never add a route for them.

## 2. Offline-first, LLM-optional, honest data

- App fully works with no ONNX files, no network, no API key. Missing model shows the `Content/Assets/Models/README.md` guidance; never crash or blank-screen. AI features are disabled with an explanation when unconfigured; an unreachable LLM server falls back to the offline path silently.
- All LLM calls go through `ILlmService` (OpenAI chat-completions compatible: OpenAI, Azure-compatible gateway, Ollama, LM Studio, llama.cpp server, vLLM). Config (base URL, model, key, temperature, max tokens) lives in Settings, persisted to `%LocalAppData%/IELTop/settings.json`; the key is AES-GCM encrypted with a per-machine key, never plaintext in file or log. Every call is async with `CancellationToken`, network/timeout handling, and a short English error. Validate via `LlmConfigValidator` before calling; Settings changes toggle AI buttons immediately (never an enabled button that always fails); "Test connection" tests only the on-screen config and never saves. Vision is opt-in, default off (`LlmVisionEnabled`); never send images when off or unsupported.
- No heavy dependencies; import/export is text only, never auto-add OCR or GPU. Content (papers, answers, phonetics, examples) comes only from reusable licensed sources and records `source`. Never invent scores or AI results. Every AI or Mock Test band score is labeled a practice estimate, never an official IELTS score.

## 3. Code layout

- `IELTop.Core` (shared, `net10.0` max; no `net10.0-windows`, `System.Windows`, `NAudio`, `System.Speech`, DPAPI), `IELTop.Desktop` (MAUI/WebView2 + React, Windows), `Content` (read-only shared assets), `IELTop.Tests` (xUnit for window-free logic: policies, trackers, engines with fake ports), `tools/` (Python helpers, per-directory conda `.venv`, separate from C#).
- `Core/Models/`: pure entities (no DB, ONNX, platform). `Core/Data/`: `AppDbContext` plus migrations/seeds only. `Core/Services/Ai/`: all ONNX and LLM code (`StudyPrompts.cs` included). `Core/Services/Exam/`: window-free engine plus `IExamSessionController` port for all out-of-app behavior (fullscreen, focus, always-on-top); default `NullExamSessionController`, Windows host `MauiExamSession.cs`, pure helpers `StrictModePolicy` / `StrictFocusTracker`; exam window keeps only `CloseGuard` (real phase; direct close after submit/cancel); main-window `FullscreenOnStart` lives in `MainWindowPreferences.cs`, called from `App.CreateWindow`. `Core/Services/App/`: one service per screen, returning plain-data snapshots. `Core/Services/Learn/`: `LessonService` (reads `Content/Assets/Lessons/` JSON, one file per unit, original wording, `source`, ingested by `tools/lesson-ingest/`) and `StudyService` (SQLite sessions; chat/practice need a model, lesson/vocab reading works offline; question types `gap`, `completion`, `single`, `multiple`, `short`, `match` where match uses `MatchRowsJson` `{label,answer}` and answers `label=value;...`; per-question parser with exactly 1 retry on bad model JSON; chat tools via `study.chat.runTool`: lookup, translate, summarize, flashcards, fix, paraphrase). `Audio/` and `Storage/` per feature.
- `Desktop/MauiProgram.cs` (host), `Desktop/Bridge/` (`BridgeRouter`, JSON `{ id, result }` or `{ id, error }`, English text only), `Desktop/UserInterface/` (React + Vite source), `Desktop/wwwroot/` (built UI, never committed).
- `Content/Assets/`: `Models/` (ONNX), `Exams/` (papers), `Lessons/` (normalized units), `Audio/`, `Images/`; plus `Content/servers.txt`. Add ONNX model: one `OnnxModelSlot` line in `OnnxModelRegistry.cs`. Add study content: JSON file only, no code change. Add screen: one file in `UserInterface/src/pages/` plus one bridge method.
- DI via constructor, registered once in `Program.cs`. No `ServiceLocator`, no scattered `new OnnxService()`. No global static state except `OnnxModelRegistry`. Dispose `IOnnxService`, `IContentServerClient`, and all resource holders. No dead code: uncalled bridge routes, unregistered UI-called methods, and unread service properties must be deleted; `router.Register(...)` must exactly match `call('...')` in `UserInterface/src` before reporting done.

## 4. Async, files, errors, packages

- All I/O async; pass `CancellationToken` for inference/LLM; never block the UI thread (async bridge handlers, `Task.Run` on host). SQLite: `EnsureCreated()`, short queries, dispose contexts. `Path.Combine` only. DB in `%LocalAppData%/IELTop`, models in `Content/Assets/Models`, user content in `%LocalAppData%/IELTop/content`; `Content/` is read-only at runtime. Never commit `.onnx`, `.db`, `.sqlite`, `settings.json` (keep `README.md`, `.gitkeep`, `phoneme-map.json`). New content folders need `CopyToOutputDirectory` in `IELTop.Desktop.csproj`. Preferences (exam font size, fullscreen) persist to `settings.json` immediately, no Save button wait.
- English code, namespaces, commits. `I` prefix for interfaces, `Async` suffix for async methods. No cryptic abbreviations, no restating-what-it-does comments (why only).
- No empty `catch`, no raw exceptions in UI. Services return `bool + out error` or an explicit result; model-load errors name slot, missing file, and full path.
- No vulnerable packages: run `dotnet list package --vulnerable --include-transitive` before reporting done; fix NU1902/NU1903 by direct upgrade; document any forced pin with a reason. Never commit models, `node_modules`, or `wwwroot`.

## 5. ONNX

- Load only via `IOnnxService.TryLoad(name, out error)`; private `SessionOptions` per session, `ORT_ENABLE_ALL`, CPU first. Whisper audio: WAV 16kHz mono 16-bit. No absolute model paths. Code must build and demo-run with zero models installed.
- Registry: every `OnnxModelSlot` points to a real downloadable model with `Source` + `License` (non-commercial such as CC-BY-NC-SA noted in code, `Models/README.md`, and Settings UI, which must display both fields per slot). No placeholder slots. Each model consumer declares `const string SlotName`. `IsComplete` checks all slot files (model plus vocab/spiece/config), never one file. Adding a model also adds the `csproj` copy line and must appear under `bin/.../Assets/Models`; `--selftest` prints `N slot(s), M installed` and fails when a required slot is missing.
- Lazy loading only (never at startup); on-demand by default, or preloaded per exam via `ModelLoadCoordinator.PrepareAsync` / `ReleaseAfterUse` when "Keep ready" (`AppSettings.ModelAutoLoad`) is on (`WritingSlots` = `gec-t5-small`, `SpeakingSlots` = whisper + wav2vec2). Live model check (file existence is not enough): `IELTOP_ONNX_LIVE=1; dotnet test --filter FullyQualifiedName~OnnxModelsLiveTests` (TTS speaks, STT listens back, wav2vec2 scores correct higher than wrong, GEC fixes a bad sentence; models read from `Content/Assets/Models`).
- Pronunciation uses wav2vec2 CTC phoneme-level MDD, never vanilla Whisper; client uses Base INT8; IPA only (`phoneme-map.json`, no ARPABET mix; rerun `tools/speaking-mdd/check_phoneme_map.py` after model change; quantize `MatMul`/`Gemm` only, Conv is not quantizable). Score is GOP 0..1 per phoneme (`PhonemeEdit.Gop`), averaged per word and per attempt (`MddResult.MeanGop`); weak-but-matching phones are still flagged; verify via `--model-server` + `/v1/pronunciation/check`, never by eye. Fluency is measured from audio (`SpeechTiming.cs`: 20ms energy VAD, 100ms hangover, 250ms pause floor) into `MeasuredSpeechSeconds` / `PauseCount` / `MeanPauseSeconds`, shown via `SpeechTimingLabel`, fed to the grading prompt and capped by `ApplyPaceCap` (practice heuristic, not an IELTS standard).
- Piper TTS needs both `espeak-ng.exe` and `libespeak-ng.dll` under `espeak-ng/` (missing DLL exits `0xC0000135` with empty wav); 4-D VITS output `[1,1,1,N]` takes its length from the last dim.
- `--model-server` (`OnnxHttpServer` in `Core/Services/Protocol/`) is loopback HTTP-only with a bearer token at `%LocalAppData%\IELTop\model-server.json`; routes `/health` (shows `provider` and loaded slots), `/v1/stt`, `/v1/tts`, `/v1/pronunciation/check`, `/v1/grammar/check`; audio as base64, never paths; docs in `tools/onnx-server/README.md`.
- Execution provider: Core keeps CPU (`IOnnxExecutionProvider`); Windows host adds DirectML (`Microsoft.ML.OnnxRuntime.DirectML`, `DirectMlExecutionProvider` probing `Win32_VideoController` while skipping virtual/Basic Render and Windows-reported broken/disabled cards via `Status` + `ConfigManagerErrorCode`, falling back to CPU). Extra exclusions via `IELTOP_GPU_BLOCKLIST` (`;`-separated substrings). No hardcoded vendors; Core has no Windows dependency.
- STT slots are `stt-whisper-{small,base}-en` (tiny removed as too weak); `ResolveSttSlot()` picks the largest installed; dropping files into `Content/Assets/Models` switches automatically, no code change.
- Speaking defaults to test mode: mic test first, single recording, stop submits and grades; STT transcript is read-only (`SetTranscript` rejected). `AppSettings.SpeakingAutoSubmit` (default true) off keeps the transcript editable for practice; `run.SpeakingAutoSubmit` informs the UI.
- Speaking tutor (Study tab): original offline `SpeakingBank` cues (Part 1/2/3 plus read-aloud) plus `SpeakingTutorService` (`study.speaking.*`, `Kind=Speaking`, `TutorSpeakingAttempts`). Cue answers need STT + VAD + `ClarityAsync` (no reference text); read-aloud needs MDD only (GOP plus word table; STT for display). Missing models means a refusal with reason, never a partial save; detailed feedback needs LLM (`StudyPrompts.SpeakingFeedback*`, `InvariantCulture` numbers); page recording uses shared `blobToWavBase64` in `audio.ts`.

## 6. Exams, history, import/export

- Papers are `Content/Assets/Exams/*.json` (`skill`, `minutes`, `material`, `questions`, `source`); never hardcode content. UI matches real computer-delivered test: single screen, countdown, part navigation, one question per block; answers stored per part, all parts graded on submit; Writing collects essays with no auto-score (teacher or AI note required); timeout auto-advances, final timeout auto-submits; review screen after submit.
- Listening audio comes from `Content/Assets/Audio/`, served by the host as `/media/audio/` URLs (never `file://`); a missing file is named in the UI with a transcript fallback, never fake TTS or a crash. Multiple-choice grading is local so offline works.
- `ExamAttempt.Scope` derives from real parts (`Full test` for 4 skills, else `+`-joined such as `Listening + Reading`); never hardcode it. Results skill filter uses substring match (`Contains`).
- Import reads text only: txt, md, json, csv, pdf, docx via `FileTextExtractor` (scanned PDFs reported unsupported). Without LLM, import still saves raw text for manual questions; with LLM it drafts questions the user must review before saving. User content goes to `%LocalAppData%/IELTop/content`; export writes JSON/Markdown into a fresh folder per run, never overwriting.

## 7. Agent workflow

1. Read `IELTop.Core.csproj`, `IELTop.Desktop.csproj`, `Program.cs`, and related files before editing. Make the smallest change possible; prefer existing files; no new `.md` files unless asked.
2. After C# or web UI changes: `dotnet build IELTop.slnx --nologo -v minimal` from repo root until 0 errors (this also rebuilds the web UI).
3. Headless check first: `IELTop.Desktop.exe --selftest` (one line per check, no window; exit 0 pass, 2 fail; append `--live` for real-model/LLM checks via `llm.txt`). Every new feature needs a `--selftest` line or a test so regressions are caught without opening a window (`dotnet test --filter "FullyQualifiedName~StudyLiveLlmTests"` skips cleanly without `llm.txt`).
4. Open a window only for real UI verification, driven via `tools/debug-desktop/launch.cmd` plus `tools/debug-desktop/cdp.ps1` (de-elevated through `explorer.exe`, since an elevated shell makes WebView2 ignore `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`; the `?k=` page key is secret and never logged). Full guide: `tools/debug-desktop/README.md`.
5. Read logs instead of guessing: `%LocalAppData%\IELTop\logs\latest.log` plus the Settings Diagnostics tab (health counters, slowest call, log tail, level, markers). `BridgeRouter` logs every call (timing plus redacted args); extra logging uses `AppLog.*`, never scattered `Console.WriteLine`. `IELTOP_LOG=trace|debug|info|warn|error` sets verbosity (`Info` hides per-call lines; use `Debug`/`Trace` to see them); log files stay readable while open (`FileShare.ReadWrite`).
6. No commit, push, or git config changes unless asked. Reply briefly in English with changed files as `path:line`.

## 8. Done checklist

- [ ] `dotnet build` 0 errors; `--selftest` passes (14/14, or 16/16 with `--live`); no strange `ERROR` lines; Diagnostics Healthy.
- [ ] UI text all English; no new em/en dash or emoji; no sub-12px text; multiline input is top-aligned `<textarea>`; no dead buttons; every sidebar item opens a real screen; no glyph labels; `lucide-react` icons only.
- [ ] Single style system (Tailwind + `styles.css` tokens; `ui/` vs app `components/` split; exam tokens separate; square exam corners); theme Light/Dark/System works, default `System`.
- [ ] No raw tech terms in UI; band scores labeled practice estimates; app works with no models, no network, no key; AI calls via `ILlmService` only; key encrypted; AI buttons track config; no-LLM import still saves text; user content in `%LocalAppData%/IELTop/content`.
- [ ] Bridge routes exactly match `call('...')` (no extras, no gaps); each slot shows `Source` + `License`; Mock Test grades all parts on submit with review; no vulnerable packages (`dotnet list package`, `npm audit`); no models/`node_modules`/`wwwroot` in git.
